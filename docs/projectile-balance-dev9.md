## 模式与费用

- 普通发射：成功生成每个原生载荷时收费一次。环刃／玫瑰后续多目标、回返接触不重复收费，但每次原生 hurt 接受都续接后续 Ars 效果；连续同 tick 的无敌帧拒绝不续接。后续 Ars 效果自身费用另算。
- 散射：每个载荷独立付费，受 Core VolleyBudget 预算限制。实际 Ars 5.13.3 与 4.12.7 的一份 Split 增加一发，总数是两发；不会按三发估价。环刃一份 Split 的基础总价 10＋20＋2×40＝110，玫瑰为 130；碎晶为 190（该碎晶散射总价是按既有共同预算规则静态推导）。
- 环绕等重复载体：生成时不扣载荷费，每次有效命中收取整份报价。环刃／玫瑰为每次 40／50；碎晶为每次 80，不分裂。友军和拒绝 hurt 的环刃命中不付费，空资源结束执行。提高实体数量并不产生免费重复载荷。
- 单发碎晶：分裂子晶继续保留伤害与虚弱，不额外付费、不重复分裂、不续接 Ars。主晶增强每级尺寸 +0.2、伤害 +2，尺寸最大 2；子晶固定 0.5。增强同时增加 Ars 20 和载荷 10，因此单发一级增强总价 120，主晶基础 12；超过尺寸上限不会继续提高伤害。

## 编排校验修正

发现旧版源码与真实施法测试支持碎晶增强，但只把替换魔符加入形态兼容列表，没有加入 Amplify；纯海灵环境下，原生书内 AugmentCompatibilityValidator 会拒绝弹射物 →碎晶 →增强，其他附属可能掩盖该缺口。

本版通过已有 Core CarrierProfile 和 SpellValidators 完成接线：Neo 形态允许书写该增强，AquamiraePayloadRules 只接受含海灵碎晶的增强组合；普通 Ars 弹射物保留原先语义，环刃／玫瑰不能获得没有实现的增强伤害。其他附属的 ProjectileForm 交回自己的规则，不导入其类。不改 Core，不新增 Mixin。Ars 5 的形态增强说明也补引用替换魔符简短描述；Ars 4 没有这个说明接口，保留各魔符自己的描述。

## 服务端证据与限度

新增测试验证环刃／玫瑰的两个目标加一次回返共三次原生接受接触：基础总量 9、初费只付一次，中间立即重复接触被无敌帧拒绝。这里通过真实原生载荷与控制器模拟接触顺序，是计费／续接测试，不冒充自然飞行的命中率。既有真实飞行、回收和友军测试仍保留。

实际 Ars Scatter 测试验证两份载荷、逐发收费；资源只够一发时只生成一发，耗尽后没有免费副本。既有环绕重复命中测试验证每次付款、无敌帧拒绝免费和空蓝清理。Neo 另验证原生书内语法接受碎晶增强、普通 Ars 不接收无效增强、环刃不接收伪伤害增强；原有主晶／子晶实际伤害、续接和分裂测试保留。

首轮新散射测试误把一份 Split 按三发断言，失败后核对两版实际 MethodProjectile.summonProjectiles，改为原生两发预期；没有改变生产端散射算法。

这些证据支持本轮较温和的费用下调，不能证明复杂群体和装备组合已达到最终平衡。未启动客户端，不声称渲染、运动手感或密集群体的自然命中率已人工验证。固定 Core 受控文件未改；实际测试结果、产物和部署见 [dev.9 交接](handoff-dev9.md)。
