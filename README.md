# Aquamirae & Nouveau

独立的海灵物语与 Ars Nouveau 联动附属，使用 Ars Conflux 中立 API。
显示名称：**Aquamirae & Nouveau**；Mod ID：`aquamirae_nouveau`；作者 EndXiom；附属代码许可 MIT。
当前版本 **0.1.0-dev.1**。原模组由 Obscuria 开发；本项目不代表其官方，也不打包原模组代码或素材。

| 平台 | Java | 原模组验证基线 | Ars 验证基线 |
| --- | --- | --- | --- |
| NeoForge 1.21.1 / 21.1.250 | 21 | Aquamirae 7.2.11 / Fragmentum 5.2.0 | 5.13.3 |
| Forge 1.20.1 / 47.4.0 | 17 | Aquamirae 7.1.14 / Fragmentum 5.2.0 | 4.12.7 |

需要独立安装 Ars Nouveau、Ars Conflux 0.1.15、Aquamirae 及其前置。
其他法术附属不是必需依赖。两平台共用 `common/` 源码和 `VERSION`。

| 魔符 | 平台 | 默认触发耗蓝 | 默认冷却 | 行为 |
| --- | --- | ---: | ---: | --- |
| 护甲碎裂 | 两版 | 40 | 2 秒 | 原生护甲碎裂，12 秒，每层降低 10% 护甲，最多 5 层 |
| 生命碎裂 | 两版 | 60 | 3 秒 | 原生生命碎裂，12 秒，每层降低 5% 生命上限，最多 10 层 |
| 深海之怒 | 两版 | 60 | 5 秒 | 原生深海之怒属性，30 秒，每层增加 10%，最多 5 层 |
| 深海韧性 | 两版 | 60 | 5 秒 | 原生深海韧性属性，30 秒，每层增加 10%，最多 5 层 |
| 深渊碎晶 | 仅 NeoForge | 80 | 2 秒 | 原生追踪碎晶，尺寸 1、基础伤害 10，虚弱 I / 50 tick，碎裂后分出三个尺寸 0.5 的子碎晶 |

所有魔符属于 **效果**，Tier 1。原版 Ars 形态和增强的费用仍由 Ars 收取。
每个成功触发单独支付上述载荷费用；每个书写增强额外支付 10 Mana。
没有适用实体、原生效果未改变、空蓝或生成实体失败时不支付载荷费用；创造模式免载荷费。
形态与后续效果仍遵循原生 Ars 行为；不将选中的实体变成施法者、伤害所有者或付款者。

两个碎裂魔符每次成功触发追加一层，增强再加层数，受各自上限限制。
深海之怒和深海韧性默认一级，增强增加等级，同级重复触发只刷新持续时间，不累加层数。
延时为每个原生状态增加默认 200 tick（10 秒），总时长最多 72000 tick。
深海属性的装备和伤害收益完全由原模组处理；它们不是固定的最终伤害或减伤百分比。
生命碎裂降低的是生命上限，原生移除与健康值处理保持不变；效果结束不会自动补血。

深渊碎晶沿触发入射方向发射；无入射方向时使用执行者朝向。保留本体敌对目标筛选、追踪、液体阻力、虚弱、分裂、200 tick 生命周期、客户端实体渲染和声音。
增强将原生尺寸每次加 0.2，尺寸上限 2，相应提高原生伤害，并改变其原生追踪建立速度；子碎晶仍固定尺寸 0.5。
它是发射实体的效果，后续 Ars 效果仍在原触发位置执行，不附着到碎晶命中；不替换 Ars 弹射物轨迹，不额外添加 Ars 命中回调。
单次触发包含原生分裂，子碎晶不再次扣费。已发出的碎晶沿用原生生命周期，所有者死亡不会额外取消它。
Forge 7.1.14 没有该实体，因此不注册深渊碎晶、配置或获取配方。

例如：`弹射物 → 护甲碎裂 → 伤害`，或 `自身 → 深海之怒`。
获取使用 Ars **抄写台**原生配方，均消耗魔源宝石 ×1 和 27 XP，另消耗：

图标只运行时引用本体物品贴图。未复制本体图片或实现。

世界 `serverconfig/aquamirae_nouveau-server.toml` 可调整触发费用、增强附加费、状态时长、延时时长和冷却。
冷却通过 Conflux 的主动施法 API 在确认释放时按施法者、按魔符记录；换工具不能绕过。
同次编排重复魔符只记录一次冷却，已有弹射物、环绕和其他后续触发继续执行；自动装置与被动 resolver 不作为新的主动施法。
创造模式默认绕过冷却，可通过 `creativeCooldown` 启用；`cooldowns.enabled` 全局关闭，某个 `cooldowns.seconds` 设为 0 仅关闭该魔符。
未命中也会记主动释放冷却；是否扣载荷费取决于后续效果是否成功触发。

在自己的工作树及固定 Conflux 检出目录构建；依赖放在忽略的 `libs/`、`forge/libs/`，哈希见各自 `dependencies.lock.json`。
NeoForge 在根目录用 Java 21；Forge 在 `forge/` 用 Java 17，各自运行 `./gradlew.bat :runGameTestServer :jar :sourcesJar --offline --console=plain`。
Forge `jar` 会执行 `reobfJar`；只使用重混淆后的最终 JAR。两版可用 `-PconfluxCheckout=...` 指定独立 Core。
根目录 `python tools/verify_release.py` 验证 NeoForge 产物，加 `--forge` 验证 Forge 产物。
`tools/generate_resources.py` 维护共享的中英文本、NeoForge 配方和贴图引用；Forge 构建转换为 Ars 4 的配方格式。

本体差异和未接入能力见 [原生行为核对](docs/native-audit.md)，实际验证与产物见 [本批交接](docs/handoff-first-abilities.md)。
